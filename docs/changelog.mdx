**intent-create のフェイルクローズ化、スコープランナーの新規作業導線、新セッションへの引き継ぎ**: `intent-create` が、意味のある作業内容を伴わずに呼ばれた場合にフェイルクローズするようになった。`bun .claude/tools/aidlc-utility.ts intent-create` を `--scope`・`--arguments`・`--label` のいずれも付けずに実行するとエラーになり、何も変更されない。値を取るすべての作成オプション（`--scope`、`--arguments`、`--label`、`--depth`、`--test-strategy`、`--review`、`--repos`、`--project-dir`）も、値なし・空白のみの指定をパス解決や変更処理の前に拒否する。完了済みワークフローは、無関係な新しい作業に対して人間の確認を伴う `next --new-intent --scope <scope> "<description>"` の経路を案内するようになり、スコープランナー（`/aidlc-<scope>`）も完了済みワークフローで行き止まりにならず同じ導線を持つ。`next --new-intent` は空でない新規作業の説明を要求し、そのディレクティブは各ハーネスのコンダクターに対して「インテントを作成し、STOP し、ハーネスネイティブの新セッション入口（`/aidlc`、Codex では `$aidlc`）を使う」ことを指示する（新規ワークスペースの作成はセッション内で継続）。PostToolUse フックは `intent-create` の成功結果をそのツールイベントのホストセッション ID と対応づけ、既存の所有権を上書きしない。2 回目の作成では短命のワンショット引き継ぎ受領記録を書くため、Stop は要求されたクリーンなセッション境界を許可し、旧い会話が新しいインテントへ引きずり込まれることがなくなる。UUID 裏付けのある SessionEnd がスタンプを持たない場合はフェイルクローズし、`SESSION_ENDED` とそのハートビートは実際に終了したセッションにのみ記録される。Kiro IDE はレガシーな `intent-create` 呼び出しを SessionStart で保持した合成セッション識別子に束縛し、モダンな Stop イベントは自身の `session_id` をワークスペース全体のマーカーより優先するため、同時実行中のチャットが互いの引き継ぎ受領記録を消費し合うことがない。GitHub Copilot も同じ 2 番目のインテント境界に従う。**アップグレード: 更新されたツール・フック・オーケストレータースキル・スコープランナーを導入するため、`dist/<harness>/` シェルの再コピーが必要。**

**トランスクリプトを配信しないハーネスでも会話ターンを尊重する Stop フック**: Stop フックの「会話ターン適用除外」に 2 つ目の証拠源が加わり、ステージ途中の純粋な会話ターンが「進捗なし」ブロックとして数えられなくなった。従来この適用除外はハーネスのトランスクリプトから答えを読んでおり、`transcript_path` を配信するのは Claude Code と Codex だけだったため、Kiro IDE・Kiro CLI・opencode では過去の判断理由を尋ねたりコードを読むだけのターンが上限つきブロックに落ちていた。トランスクリプトが届かない場合は、アクティブなインテントの記録ディレクトリに置かれる 2 つの mtime マーカー（人間のプロンプトごとに更新される `.aidlc-human-turn` と、`aidlc-orchestrate next` / `report` / `park` が更新する `.aidlc-engine-touch`）で同じ問いに答える。人間ターンが最後のエンジン前進より新しければ会話ターンと判定される。どちらも出荷済みの gitignore ルールの対象でコミットされることはなく、読み取り専用の経路（`--status`、`--doctor`、`--help`、`--version`、ワークスペース系動詞）は関与とみなされない。**見え方はホストによって異なる**: Claude Code・Codex・opencode では余計な催促が抑制されてターンがきれいに終わり、Kiro IDE では利用者に見える変化はない（同ホストの `Stop` は観測用でそもそも催促が届いていなかったため、`stop.drops` の記録と進捗なしカウンターだけが是正される）。Kiro CLI 2.16.0 では legacy/V2・`--v3`/KAS の両ランタイムで催促が抑制されることが実測された。**既知のギャップは塞がずに文書化**: マーカー経路はトランスクリプト経路より緩く、`aidlc-jump`・`aidlc-bolt`・`aidlc-swarm` および変更を伴う `aidlc-state` の各動詞にはエンジンマーカーを触るものが無いため、ステージポインターを飛ばしてからエンジンに相談せずターンを終えたコンダクターは Kiro と opencode では解放される。マーカーはインテント単位でセッションキーを持たないため、同一インテント上の 2 セッションが相互干渉しうる点も含め、`docs/reference/06-hooks-and-tools.md` に明記された。強制自体は健在で、エンジンに相談してから報告せずに終えようとするコンダクターは引き続きブロックされ、自律コンストラクション下では適用除外が抑制され、マーカー読み取りは 2 つともフェイルクローズする（書き込みに失敗したマーカーは古いまま残さず削除される）。コマンド・フラグ・出力形式の変更はなく、CI やスクリプトへの破壊的変更もない。**アップグレード: 各ハーネスのツリー内容をコピーする（例 `mkdir -p your-project/.kiro && cp -R dist/kiro-ide/.kiro/. your-project/.kiro/`）。**

## 2.5.58
- 日付: 2026-08-07（コミット 8c60e1a、8/8検知）
- 種別: fix

**隣接して書かれたソースタグでも主張を接地する**: `claim-sources` センサーが、区切りなしで隣り合うソースタグを見失わなくなった。`[Q1][Q2]` が Markdown の参照リンク構文になるのは、そのラベルを文書自身が定義しているときだけであり、定義がなければ CommonMark は両方のタグをそのままの文字として描画する。センサーもこれと同じ読み方をするようになったため、2 つの回答を区切りなしで引用した主張が「未接地」と報告されることはなくなった。折りたたみ形 `[Q1][]` も同様に扱われ、逆に文書が実際にリンク参照として定義しているタグ（ショートカット形 `[Q1]` を含む）は何も接地しないという、これまで取りこぼしていた鏡像も正される。リンク参照定義だけからなる段落は、ソースタグを欠いた主張ブロックとは見なされない。定義に「見えるだけ」の行（閉じられていない `<...>`、括弧の不均衡、`(...)` タイトル内のエスケープされていない `(`）は、読者に見えるとおりの散文として検査対象に戻り、ブロック引用やリスト項目の中にネストした定義も順序と深さを問わず読み取られる（リストマーカー後の 5 個以上の空白は従来どおりインデントコードブロック）。**アップグレード: `dist/<harness>/` シェルの再コピーが必要。**

**AI-DLC がフレームワークの用語ではなくプロジェクトの言葉で話す**: 利用者から報告された 3 つの事象は同じ原因に行き着いた。アシスタントが内部構造をそのまま実況していたこと、フック名やメッセージが目的ではなく配管を説明していたこと、そして新しいワークフローが決して使わないフォルダとともに始まっていたことである。チャットメッセージ、承認ゲート、コンポーザーの計画提案、スコープの質問、エラーメッセージ、オンボーディング文書が平易な開発者の言葉で書き直され、手順の合間の文はアシスタントの即興ではなくフレームワークが書いたものを中継する形になった（何も書かれていない場面は沈黙が既定）。7 つのフックとインテント作成コマンドが、その働きを表す名前へ改名されている（`aidlc-audit-logger` → `aidlc-write-audit-log`、`aidlc-sync-statusline` → `aidlc-sync-workflow-state`、`aidlc-mint-presence` → `aidlc-record-human-turn`、`aidlc-runtime-compile` → `aidlc-rebuild-stage-graph`、`aidlc-stop` → `aidlc-continue-workflow`、`aidlc-dispatch-rules` → `aidlc-deliver-stage-rules`、`aidlc-sensor-fire` → `aidlc-run-sensors`、`aidlc-utility intent-birth` → `intent-create`）。記録ディレクトリに作られるフォルダは、スコープが実際に実行するフェーズの分だけになった（`bugfix` や `refactor` には `ideation/` も `operation/` も作られない）。ステージ単位のフォルダは事前に作られず、そのステージが最初に成果物を書き込んだときに現れる。挙動は一貫して変わっておらず、ステージ・承認ゲート・監査イベント・ツールフラグはすべて同一である。**アップグレード: `dist/<harness>/` シェルの再コピーが必須（任意ではない）。古いフックファイルと `settings.json` の項目は旧名を参照するため、コピーが古いままだと旧配線が使われ続ける。Kiro IDE 利用者は先にインストールガイドの退役フック掃除を実行すること（オーバーレイコピーでは自動検出された旧登録を削除できず、放置すると新旧のフックが同時に発火する）。Codex 利用者はフック信頼の事前シード（`bun scripts/package.ts codex trust --project <abs-dir>`）を再実行すること。信頼ハッシュがアダプターのコマンド文字列を含むため、改名対象すべてでハッシュが変わる。**
